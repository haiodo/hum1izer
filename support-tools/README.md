# support-tools

Инструменты замера формы кода. В поставку hum1izer не входят: каждый лежит
отдельным модулем, `go build ./...` в корне их не видит.

Появились из замера по 33 корпусам, 7 языкам и 587 тысячам функций: ядро Linux,
PostgreSQL, sqlite, coreutils, Go stdlib, CPython, tokio, ripgrep, платформа
Eclipse и несколько рабочих репозиториев. Как его повторить - [METHOD.md](METHOD.md).

## shape - метрики через tree-sitter

Цикломатика, длина, глубина вложенности и число параметров на функцию.
Языки: Go, C, Java, TypeScript, TSX, Python, Rust, C#.

**Требует CGO** - отсюда и отдельный модуль. Грамматики собираются из
исходников, первая сборка занимает около пяти секунд.

```bash
cd shape && go build -o probe .

STATS=1 ./probe ~/src/myrepo          # персентили и доли нарушителей
TINY=1 STATS=1 ./probe ~/src/myrepo   # доля тривиальных функций
CROSS=1 STATS=1 ./probe ~/src/myrepo  # пересечение глубины и цикломатики
CSV=1 STATS=1 ./probe ~/src/myrepo    # то же одной строкой CSV
ERR=1 ./probe ~/src/myrepo            # сколько файлов не разобралось
DUMP=1 ./probe file.c                 # имена узлов грамматики
```

Вместо каталога можно передать файл со списком путей - по одному на строку.

Функции, внутри которых парсер поставил ERROR, отбрасываются. Для C это важно:
препроцессор ломает разбор в 36-75% файлов, и без отбраковки функция «съедает»
остаток файла. `winWrite` в sqlite намерилась в 19703 строки при реальных 104.

## depth.py - глубина без парсера

Та же глубина вложенности по отступам. Парсер не нужен, работает на любом
языке с отступами - `tenniarb` снят именно им, для Swift грамматика
tree-sitter не собирается из коробки.

```bash
python3 depth.py ~/src/myrepo
```

Медиана, p90 и p95 совпадают с разбором дерева. Хвост завышен примерно вдвое:
gofmt даёт `switch` два уровня отступа там, где дерево видит один. Поэтому
порог по отступам - 5, а не 4.

Шаг отступа определяется модой разниц между уровнями, а не минимумом.
Наивная версия на одном из проверочных репозиториев выдала `depth>4` = 13.3%
вместо 0.0%: выравнивание продолжений строки даёт разрывы в один-два пробела,
и минимум ловит их.

## years.sh - срез репозитория по годам

Состояние на конец каждого года через `git archive`, рабочая копия не трогается.

```bash
./years.sh ~/src/postgres src/backend 1996 2026 > data/postgres.csv
```

## erosion - метрики из SlopCodeBench

Erosion и доля клонов по формулам из поста
[Measuring the sloppiness of code](https://earendil.com/posts/measuring-code-sloppiness/).
Только Go, через `go/ast`, без зависимостей.

```bash
cd erosion && go build -o erosion . && ./erosion ~/src/myrepo
```

Обе метрики замер не подтвердил: erosion у живых репозиториев вышла 0.52-0.91
против обещанных постом 0.31 +- 0.17. Оставлено для воспроизводимости.

## rcs.py - исходники из CVS

Достаёт head-ревизию из `,v` файлов, когда рядом нет ни `cvs`, ни `rcs`.

```bash
python3 rcs.py ~/archive/cvsrepo ./out
```

## data

Ряды по годам в CSV: год, функций, cc50/90/95, sloc50/90, depth95 и доли
нарушителей порогов: PostgreSQL за 30 лет, eclipse.platform и
eclipse.platform.swt за 25, dltk.core за 18, org.eclipse.rcptt за 11 и
tenniarb на Swift.

`corpora.csv` - список всех корпусов замера: язык, версия, объём в строках по
`cloc`, число функций, история из git и адрес источника.
